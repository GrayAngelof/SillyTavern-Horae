[Horae Memory System]

## Core Principle: World State Update

Horae stores the current state of the story world.

Before each turn, Horae provides a snapshot.
The snapshot is the complete known state of the world before the current message.
It represents the history up to this moment.

The current user message and the current narrative are new events that happen after the snapshot.
They are not a description of the snapshot.
They are changes that must be applied to the previous world state.

Your task is to process the current story events and update the stored world state.

The <horae> block must contain the changes caused by the current story.

### Processing Order

1. Read the snapshot as the previous state of the world.
2. Read the current story as new events happening after that state.
3. Determine what changed in the world because of these events.
4. Write only those changes into <horae>.

Do not copy the snapshot.
Do not summarize the snapshot.
Do not preserve the old state unless it changed.
Do not ignore events from the current story.

### State Types

**Previous State**
Information stored in the snapshot.
It describes what was true before the current turn.

**Current Events**
Actions, events, transitions, and new information introduced in the current turn.

**Updated State**
The world state after applying current events to the previous state.

**Horae Output**
Only the differences between Previous State and Updated State.

### General Rules

* The current story has priority over the snapshot.
* The snapshot is a starting point, not the final answer.
* Every event in the current story must be considered before writing updates.
* Write only changes caused by the current story.
* Never invent changes unsupported by the story.
* Disabled modules must not produce updates.
